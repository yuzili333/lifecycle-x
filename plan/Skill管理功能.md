## 计划

你是一名资深 Agent 开发工程师。

我正在优化【存续期业务数据探针智能体】的Skill管理功能模块。

请使用 Plan 模式工作：先进行模块分析和方案设计，不要直接写代码。

【现状】

已经支持的功能：

1. 本地 Skill 查询；
2. 本地 Skill 选择；
3. 本地 Skill 加载；
4. Skill 元数据解析；
5. Skill 内容读取；
6. Skill 可用性校验；
7. Skill 分类、标签、关键词检索；
8. 对话输入框中输入 `@` 时唤起 Skill 选择弹层；
9. 输入 `@关键词` 时实时筛选 Skill；
10. 通过键盘或鼠标选择 Skill；
11. 将选中的 Skill 以可解析的 mention token 方式插入输入框；
12. 在发送消息或执行 Agent 任务时加载已选择 Skill；

本地已经预置Skill：
1. overall-risk-classification-distribution；

【核心目标】

1. 默认开启Skill功能，用户设置中不再提供“开启/关闭”功能；
2. 用户设置弹窗中，将`Skill`配置从“模型配置”菜单中剥离出来，单独新增一个“技能”菜单；
 - 提供手动安装`Skill`入口，新安装`skill`默认开启使用，安装前需校验文件合法性和字段结构合法性。
 - 提供已安装`Skill`列表，每个`skill`列表项中需展示显示名称和简介、分类（系统或个人）、删除按钮、是否开启的`Switch`（仅个人skill提供）。
 - 列表中区分客户端预置`skill`和用户自定安装`skill`，预置`skill`显示分类“系统”，手动安装显示分类"个人"。
3. 删除存量`skill` overall-risk-classification-distribution，因需提供表头字段的映射数据不符合实际`csv`文件场景；
4. 支持预置系统`skill`;

【输入信息】
系统可能接收以下输入：
- `skill`预置文件;
- `skill`安装文件;

【期望输出】
系统最终应输出：
- 独立Skill管理菜单，支持新增、查看、删除。
- 区分预置和手动安装`skill`。
- `ChatComposer`支持选择预置和个人`Skill`

【标准】
请按照以下标准设计方案：
1. 输出必须可被用户引用作为判断依据，禁止输出定义不明确、模糊不清的分析内容；
2. 模块职责必须清晰；
3. 数据流必须可追踪；
4. 异常处理必须明确；
5. 拆分多个 Goal 子任务；
6. 方案应适合工程落地，而不是只停留在概念描述。

【边界】
设计时必须遵守：
1. 技术栈限定为：【例如 TypeScript + Node.js + Electron + FastAPI】；
- 客户端开发语言：`Typescript`、`React`等;
- 客户端开发框架：`Electron`;
- 界面开发框架：`React`、`astryx`，列表选择`astryx`组件`List`;
- 服务端开发语言：`Nodejs`；
- 服务端开发框架：`Express`、`FastAPI`等；;
2. 不允许使用：【不允许的库 / 服务 / 架构】；
3. 不改变已有的：【API / 数据结构 / 业务流程】；
4. 不处理以下范围：【明确排除项】；
5. 如果需求存在不确定性，请列出假设，不要擅自决定。

【异常处理要求】
请在方案中考虑：
1. 输入缺失时如何处理；
2. 数据源失败时如何处理；

4. 无法完成任务时如何返回结构化错误；
5. 如何记录 fallback / retry / conflict trace。
