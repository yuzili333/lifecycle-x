# “溯据”黑客松产品介绍视频两天制作计划

## 一、制作基线

| 项目 | 已锁定方案 |
|---|---|
| 成片 | 3 分钟以内，目标 179.8 秒 |
| 产品录屏 | Kap 3.6.0，本地分段录制 |
| 旁白与剪辑 | 剪映专业版 11.3.0，本地真人旁白、剪辑、字幕、包装与导出 |
| 画面参数 | 1920×1080、30fps、16:9 |
| 数据边界 | 只使用固定、脱敏、已获授权的数据；素材不上传云端服务 |
| 叙事来源 | `prototype/黑客松项目作品介绍视频内容设计.md` |
| 默认声音 | 业务主管真人旁白；不添加授权来源不明确的背景音乐 |

Remotion、HyperFrames、Adobe、Canva、数字人、云端字幕识别和云端语音增强不进入本次制作链路。制作期间不修改 Lifecycle X 产品功能，也不增加内容设计文档以外的卖点。

## 二、最终交付

1. `溯据_黑客松产品介绍_3min_master.mp4`：本地高质量母版。
2. `溯据_黑客松产品介绍_3min_submission.mp4`：组委会提交版。
3. `溯据_黑客松产品介绍_zh-CN.srt`：经人工审校的中文字幕。
4. P01—P12 审定录屏、旁白轨及剪映最终草稿 `sujudata_v03_final`。
5. 同一成功会话的截图、报告和预录片段兜底包。
6. 素材台账、版本记录、技术验收结果和 SHA-256 校验值。

本地二进制素材统一放在已被 Git 忽略的 `output/hackathon-video/`；仓库只保存本制作计划、内容设计、自动验收脚本和任务记录。

- 产品录屏：`P02_field-selector_t01.mp4`。

- 不覆盖原素材。每次重录增加 Take 编号，每次关键锁定复制剪映草稿。

## 四、第一天：Demo 冻结、录屏与粗排

### 08:30—11:30：Golden Path 门禁

1. 研发工程师准备固定脱敏 CSV 和干净会话，业务主管核验字段、统计口径和追问路径。
2. 连续两次完成同一 Golden Path：选择 CSV → `#` 选择真实字段 → 选择整体风险分类 Skill → 计划与审批 → SQL/Python → 图表与首版报告 → 追问与第二版报告 → 溯据卡 → 导出。
3. 第二次成功会话冻结为唯一录制来源，立即保存截图、报告和预录兜底片段。
4. Golden Path 未连续成功两次，不进入正式录屏，不以单元测试或模拟结果替代业务验证。

### 12:30—16:30：Kap 录制 P01—P12

- 固定 16:9 录制区域、30fps 和 MP4 高质量导出；保留鼠标，关闭麦克风、系统声音和夸张点击效果。
- 每段操作前后保留 2 秒静止画面，每个镜头至少录制两个 Take。
- P02 真实键入 `#` 并从当前 CSV 列表选中字段；P04 展示任务计划；P05 展示待审批到运行；P06 展示真实 running→completed；P08—P10 来自同一会话；P11 展示当前报告版本的导出。
- 隐藏用户名、客户名称、账号、本地路径、密钥、通知和无关窗口。

### 16:30—19:00：素材初审与剪映粗排

1. 两人共同选择 P01—P12 审定 Take，立即补录不合格片段。
2. 剪映项目设为 1920×1080、30fps，按内容设计时间码完成 0:00—3:00 粗排。
3. 添加标题、创新角标、流程条和字幕位置占位符；业务主管完成两遍旁白试读。
4. 复制并锁定草稿 `sujudata_v01_rough`。

第一天结束门槛：P01—P12 均有合格素材；粗排可以完整播放；所有结果来自同一成功会话；第二天不再修改产品功能。

## 五、第二天：旁白、精剪、包装与交付

### 08:30—10:30：剪映内录制真人旁白

- 业务主管在安静环境完整录制三遍，再录制错句、长句和收尾句的 Pickup。
- 只使用明确可离线运行的降噪、音量和淡入淡出；出现上传或云端 AI 提示时立即跳过。
- 选择最佳版本后复制草稿，旁白以清晰度优先，通过调整镜头停留匹配语音。

### 10:30—13:00：精剪并锁定叙事

- 按旁白校准镜头；工具等待片段可加速 2—4 倍，但持续标注“真实工具执行，等待过程已加速”。
- `#` 字段选择至少可读 3 秒，图表至少 3 秒，版本切换至少 3 秒，溯据卡来源、范围和执行证据合计至少 8 秒。
- 使用轻量淡化或直接切换，不使用模板化炫技转场。13:00 后不再调整叙事结构。

### 13:30—15:30：字幕与视觉包装

- 从审定旁白稿制作或导入 SRT，不使用云端自动字幕；每行不超过 18 个汉字、最多两行。
- 统一使用 `#0F1724` 背景、`#E6EDF6` 正文、`#65D6D2` 强调色。
- 完成开场、五个创新角标、流程条和结束页；默认无背景音乐。
- 复制并锁定草稿 `sujudata_v02_picture-lock`。

### 15:30—17:00：联合审片

- 业务主管复核字段、指标、统计口径、旁白、字幕和人工决策边界。
- 研发工程师复核真实计划、审批、工具状态、Artifact 链路、加速标识和敏感信息。
- `#` 字段功能只表述为用户显式选择重点字段，不声称 Agent 只能访问这些字段。
- 此阶段只修复错字、遮挡、音画不同步和明显节奏问题。

### 17:00—19:00：导出与验收

- 母版：H.264、1080p、30fps、高质量码率、AAC。
- 提交版：H.264、1080p、30fps、约 10—12Mbps、AAC 192kbps。
- 目标时长 179.8 秒且绝不超过 180 秒。
- 使用 `node scripts/verify-hackathon-video.mjs <master> <submission>` 检查编码、尺寸、帧率、时长、音频和 SHA-256。
- 在另一台电脑完整播放后，复制最终草稿为 `sujudata_v03_final` 并冻结。

## 六、故障兜底

- Demo 无法连续跑通：停止录制并先恢复 Golden Path。
- 单个镜头无法补录：只使用同一成功会话的真实预录片段，不拼接其他数据源。
- 第二天运行不稳定：使用第一天已冻结的真实素材。
- 追问不稳定：使用内容设计文档中的已验证备选追问。
- 剪映草稿损坏：恢复上一个锁定版本，不在损坏草稿上继续修改。
- 提交文件超限：只从母版重新压缩，不重新剪辑。
