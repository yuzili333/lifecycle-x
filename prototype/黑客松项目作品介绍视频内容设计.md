# “溯据”黑客松项目作品介绍视频内容设计

## 一、视频定位

### 1.1 推荐规格

| 项目 | 建议 |
|---|---|
| 成片时长 | 3 分钟，允许上下浮动 5 秒 |
| 画面比例 | 16:9，1920×1080，30fps |
| 内容比例 | 产品实机画面约 75%，标题卡与轻量动态图约 25% |
| 讲述方式 | 单人中文旁白，产品录屏为主，不建议全程人物出镜 |
| 核心场景 | 整体风险分类分布分析及多轮报告更新 |
| 核心受众 | 黑客松评委、业务专家、技术评委 |
| 核心目标 | 让评委在 20 秒内理解价值，在 2 分钟内看到真实闭环，在结束前记住创新点 |

默认按 3 分钟设计。如果组委会另有时长限制，可按第十节的裁剪规则生成 2 分钟版本。

### 1.2 视频只讲一个核心判断

> 溯据不是替银行作风险判断的聊天机器人，而是帮助业务人员完成并证明数据分析工作的受控智能体。

### 1.3 一句话品类定位

> 溯据是面向银行存续期的可验证、可对话数据分析智能体。

### 1.4 三句记忆点

1. **业务人员用 `#` 精确选字段、用自然语言提问，不再负责手写 SQL 和 Python。**
2. **报告不是一次生成的终点，而是随业务追问持续演进的分析资产。**
3. **模型负责理解，工具负责执行，Artifact 负责证明，人负责决策。**

### 1.5 收尾金句

> 让每份报告有据可溯，让每次分析沉淀为能力。

## 二、叙事结构

视频采用“问题—闭环—创新—价值”的顺序，不先解释技术架构，也不罗列全部功能。

```text
0:00—0:20  痛点与定位：为什么需要溯据
0:20—0:42  产品入口：数据、# 字段选择、Skill 与自然语言问题
0:42—1:25  核心闭环：计划、审批、SQL/Python、图表和报告
1:25—1:52  多轮探索：基于历史 Artifact 更新报告
1:52—2:18  可信证明：溯据卡与报告版本
2:18—2:34  产品完成度：PDF、DOCX、Markdown 导出
2:34—2:52  创新与孵化：领域 Skill 组合
2:52—3:00  人机边界与金句收尾
```

叙事原则：

- 前 20 秒只讲业务问题与结果，不讲框架名称。
- 中间 100 秒必须以真实产品操作为主，展示状态流转而非最终聊天回复。
- 创新点随对应产品画面出现，不集中堆在一张技术架构图上。
- 完整演示一个 Skill，其他 Skill 只用于证明可复制性。
- 不展示自动风险定性、自动预警或自动处置，避免突破产品边界。

### 3.2 主任务与追问文本

主任务建议使用（`#字段名` 必须从当前文件的字段列表中实际选择）：

> 基于 #最新风险五级分类、#贷款余额(万元) 和 #合同流水号，分析整体风险分类的笔数和贷款余额分布，生成图表和分析报告。

若演示文件中的字段名称或括号样式不同，应以 `#` 字段列表展示的真实名称为准，不要为配合脚本手工输入不存在的字段。

追问建议使用：

> 只看正常类内部细分，按贷款余额降序，并基于刚才的分析结果重新生成报告。

如果当前演示数据不包含足够的正常类内部细分，应在录制前调整为一个已验证、能够真实执行的追问，例如：

> 按贷款余额降序重新展示五级分类，并基于刚才的结果生成新版报告。

追问必须在最终演示数据上完整跑通后才能进入脚本，不为了配合旁白编造不存在的结果。

### 3.3 `#` 字段选择操作脚本

1. 先选中已上传的脱敏 CSV，确保输入框关联的是本轮分析数据源。
2. 在输入框键入 `#`，停留约 1 秒，让字段列表和字段类型清晰出现。
3. 搜索并点击风险分类字段；重复操作，选中贷款余额和合同编号字段。
4. 让三个 `#字段名` 在任务文本中完整停留约 2 秒，再补全业务问题并选择 Skill。
5. 发送任务后，后续镜头用任务计划、SQL/Python 状态和溯据卡证明这些字段已进入真实执行链。

录屏时不要完整滚动所有字段。三个与主任务直接相关的字段已经足以证明“业务人员无需记忆物理字段名，也无需手写 SQL/Python”。`#` 选择用于显式指定重点字段，不能表述为 Agent 永远不会按 Skill 需要读取其他已授权字段。

## 四、完整旁白稿

以下旁白可直接录制，语速建议控制在每分钟约 220—250 个汉字，并给产品关键状态留出短暂停顿。

> 一次存续期分析，为什么还要在数据、脚本、图表和报告之间反复切换？
>
> 这是“溯据”，面向银行存续期的可验证数据分析智能体。业务人员只需提出问题，不用手写 SQL 和 Python。
>
> 选择脱敏数据后，在输入框键入井号，就能唤起当前文件的字段列表。业务人员可以直接选定风险分类、贷款余额和合同编号；这些不是普通文字，而是经过客户端确认的结构化字段引用。
>
> 再选择整体风险分类 Skill，直接用业务语言发起任务。Agent 优先使用已确认的字段映射和授权 Schema，把任务拆成查询、统计、绘图和报告步骤，而不是直接编造答案。
>
> 执行前，本地系统检查权限、参数和安全规则。模型可以规划，却不能绕过确定性安全门。
>
> SQL 只读并生成受控数据集；Python 完成去重、分类、金额统计和对账，随后生成图表与报告。
>
> 存续期分析不会停在第一份结果。业务人员可以继续调整范围、维度或排序。系统引用上一轮 Artifact 和口径继续执行，生成新版图表与报告，同时保留原始版本。
>
> 报告也不是让模型自己证明自己。溯据卡由系统根据真实工具和 Artifact 记录构建。每个重要指标都能回到数据、口径和执行过程，证据不足就不会标记为已验证。
>
> 当前报告版本还能导出为 PDF、DOCX 或 Markdown，用于复核与归档。
>
> 同一架构已沉淀为多个存续期 Skill。业务专家定义口径，工程师把经验编码成可复用能力。
>
> 溯据——让每份报告有据可溯，让每次分析沉淀为能力。

## 七、录制前准备

### 7.1 演示环境

1. 使用固定、脱敏、已获授权的演示数据，确保包含主任务和追问所需字段。
2. 验证在选中该 CSV 后键入 `#` 能正常唤起字段列表，并能选中风险分类、贷款余额和合同编号字段。
3. 新建干净会话，不保留测试失败、调试信息和无关历史消息。
4. 预先验证整体风险分类 Skill 能连续完成 SQL、Python、两张图表、报告和溯据卡。
5. 确认报告版本切换和 PDF、DOCX、Markdown 导出均可用。
6. 确认四个系统 Skill 在选择器或 Skill 管理页中正常显示。
7. 关闭通知、聊天软件、系统升级提示和可能暴露个人信息的菜单栏项目。
8. 隐藏用户名、客户名称、账户号、本地绝对路径、API Key 和数据库连接信息。
9. 将应用窗口固定为 16:9 可读区域，正文缩放保持 100%—125%，避免文字过小。

### 7.2 录制顺序

建议先跑通一次完整演示并保留成功会话，再按 P01—P12 分段录制。每个操作前后多留 2 秒静止画面，便于剪辑。

工具等待时间可以加速，但需在画面角落持续标注：

> 真实工具执行，等待过程已加速

不得通过后期修改指标、拼接不同数据源的结果，或把失败结果剪辑成成功状态。

## 八、剪辑与视觉规则

### 8.1 节奏

- 开场 20 秒平均每 3—5 秒切换一次画面。
- 核心操作区保持鼠标动作完整，不因追求速度剪掉关键状态变化。
- 图表、版本、溯据卡至少各停留 3 秒，让评委真正看清。
- 等待模型或工具执行时使用 2—4 倍加速，不使用长时间转圈画面。
- 每一镜只强调一个判断，旁白不要同时解释多个技术概念。

### 8.2 字幕

- 全程添加中文字幕，旁白字幕每行不超过 18 个汉字，最多两行。
- 功能字幕描述“用户得到什么”，例如“连续追问，动态更新报告”。
- 创新角标描述“系统为何不同”，例如“证据由系统构建，不由模型自证”。
- 不在同一画面同时叠加旁白字幕、三行功能说明和复杂架构图。

### 8.3 声音

- 旁白语气平稳、专业，不使用夸张宣传腔。
- 背景音乐保持低音量，无人声；工具执行完成、报告打开和版本更新可使用轻提示音。
- 旁白优先级最高，音乐响度应始终低于旁白。
- 不保留鼠标连续点击、键盘重击或系统通知声。

### 8.4 画面真实性

- 使用真实产品画面和真实生成物，不制作与产品界面不一致的“概念 UI”。
- 可以裁切、放大和加框，但不能改变工具状态、报告数字或证据内容。
- 如果某项能力只能用预先完成的成功会话展示，画面应标注“实机录屏”或“预录 Demo”。
- 不将单元测试、模拟适配器或静态设计稿描述为生产能力。

## 十、时长调整与兜底方案

### 10.1 压缩为 2 分钟

如果视频限制为 2 分钟，按以下顺序裁剪：

1. 将开场压缩为 12 秒。
2. `#` 字段选择保留 5 秒，只展示唤起列表和选中两个字段；四个 Skill 组合移至结束页。
3. Agent 计划和审批合并为 12 秒。
4. SQL/Python 执行只保留状态变化和流程角标，不展示等待过程。
5. 报告导出压缩为 4 秒。
6. 保留多轮追问、溯据卡和收尾金句，不得删除。

两分钟版本仍必须保留的主线是：

```text
痛点与定位
→ `#` 选择字段并发起自然语言任务
→ 计划和受控执行
→ 图表与报告
→ 多轮追问
→ 溯据卡
→ Skill 化与收尾
```

### 10.2 产品录屏异常时

- 优先使用同一成功会话中预先录制的真实片段，不临时改用虚构数据。
- 若网络或模型不可用，使用已经生成的真实 Artifact、报告版本和溯据卡演示，并在画面标注“预录 Demo”。
- 若某个次要画面缺失，删除该卖点，不使用设计稿冒充运行结果。
- 若多轮追问未稳定跑通，暂停成片输出并先修复 Golden Path；多轮探索是本视频不可替代的核心证明。

## 十一、30 秒开场独立版本

该版本可用于视频预告、报名页摘要或现场开场：

> 一次存续期分析，业务人员往往要在数据、SQL、Python、图表和报告之间反复切换。“溯据”把这条链路变成一次可验证的智能体工作流：业务人员可以用 `#` 从当前文件精确选择字段，再直接提出业务问题；Agent 负责规划，受控工具负责真实执行，Artifact 和溯据卡负责保存结果与证据。溯据——让每份报告有据可溯，让每次分析沉淀为能力。
