# 旁白与声音脚本

## 1. 表演方向

- 00:00—00:36采用“对白式旁白”：对白来自镜头中的人物，但不要求画面出现完整口型；让任务、排期、追问和能力沉淀真实发生，不由全知旁白代为解释。
- 00:36—01:30由林主管接过第一人称旁白，像她在评审现场亲自操作，而不是逐项播报功能。
- 声线：成熟、可信、专业，不端着，不煽情；所有技术词清楚，不为追镜头强行加速。
- 情绪弧：临时任务进入 → 跨角色协作受阻 → 会议追问暴露静态报表边界 → 业务知识与研发能力共同沉淀 → 产品实证 → 克制收束。
- 停顿：S02“数据”后停0.2秒；S08“Skill”后停0.25秒；S09破折号后停0.35秒；最终金句破折号后停0.25秒。

## 2. 人物声音与潜台词

| 人物 | 语言习惯 | 不直接说出的内容 |
|---|---|---|
| 林主管 | 用字段、口径和报告层级说话；句子短，先给判断再给条件 | 她不怕分析，只是不愿每次都把同一套业务知识重新翻译成开发需求 |
| 研发同事 | 用排期、运行、封装等实现词；回答克制，不替业务做判断 | 他愿意支持业务，但现有协作方式让一次性需求不断挤入正常队列 |
| 参会同事 | 只问一个具体、合理的下钻问题 | 报告没有错，只是会议中的问题不会停在预设页码上 |

## 4. 剧本化表演基线

以下场景用于指导人物表演和声音设计；正式录音文字仍以第3节为准。

```text
INT. 存续期业务办公区 — 上午

墙上时钟刚过九点。林主管的电脑亮起任务提醒。她把上一期风险报告拖到空白模板旁。

参会同事（画外）
林主管，下午会前，风险分布能补一版吗？

林主管翻开数据字典，在纸上圈出三个字段。

林主管
口径我清楚。数据……还得有人跑出来。

她把纸转向研发同事。笔尖依次落在三处。

林主管（续）
按合同流水号，看五级分类，再带上余额。

研发同事看一眼任务看板，把需求卡放进队列，没有关掉正在运行的窗口。

研发同事
我先排进去。前面两项，还在跑。

会议桌上，报告已经打开。参会同事的笔停在“关注类”柱形上。

参会同事
关注类里，余额最大的几笔呢？

林主管翻到下一页。空白。

林主管
这一层，原来的报表没有。

她没有再新建需求单，而是在报告旁写下指标、流程和证据三组知识卡。

林主管（续）
口径别只留在这张需求单里。

研发同事把三组知识接入 Skill 构建界面。受控工具节点依次点亮。

研发同事
那就封成 Skill。下次，你直接问。

完成标识亮起。林主管的手回到自己的鼠标上。

林主管（画外）
这套做法，我们叫它——溯据。

INT. 溯据客户端 — 连续

真实产品操作接管画面。林主管以第一人称讲述她正在完成的动作：选字段、选 Skill、确认计划、批准工具、查看两版报告与溯据卡。她不解释“业务人员为什么需要这些功能”，画面和刚才的会议已经给出了答案。
```

## 5. 字幕规则

- 对白字幕不显示人物姓名，用声线与镜头关系区分；画外声可轻微降低环境混响，但不加“画外音”标签。
- 按语义切分，不完全照搬镜头边界；每条1—2行，每行不超过18个汉字。
- 字幕底边距离1080p画布至少72px；产品镜头使用底部独立字幕带，不遮挡输入、字段选择、Skill和审批操作。
- `#`在画面角标写作“#字段”，S10旁白读作“井号”。
- `SQL`、`Python`、`Skill` 保留英文；录音前统一确认三处发音。

## 7. 对白润色说明

- 删去“业务最懂问题”“结果只能等待”等结论句，改用林主管报字段、研发同事看队列、参会同事追问，让观众自己得出协作成本。
- 林主管始终使用口径、字段、报告层级等业务语言；研发同事只用排期、运行、封装等实现语言，任意抽掉姓名仍可辨认角色。
- “口径别只留在这张需求单里”同时回应反复沟通，并提出知识沉淀；“下次，你直接问”回应当前追问，也把控制权交回业务。
- 产品段改为第一人称现场操作，避免“系统支持、智能体实现”的说明书句式；安全边界仍通过“我确认”“只读”“不碰业务库”自然进入。
