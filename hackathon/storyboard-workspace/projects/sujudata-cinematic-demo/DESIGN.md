# “溯据”电影级演示视觉规范

## 1. 创意母题

**让一次协作，留下下一次可以直接使用的能力。**

影片不把 AI 表现为魔法，也不把研发塑造成障碍。前半段围绕一份“下午会前”要用的风险报告展开：业务明确口径，研发有正常排期，静态报表交付后又遇到自然追问。业务主管没有继续新建一次性需求，而是把指标、流程和证据口径沉淀为知识；研发同事将它们封装为可复用 Skill。后半段由业务主管亲自把新问题送入一条经用户确认、由真实工具执行的分析链：

```text
业务问题 → 字段与 Skill → 计划 → 用户审批 → SQL → Dataset → Python
→ 图表 → 报告版本 → 溯据卡 → 可复用能力
```

前半段的视觉变化是“一次性需求”经过业务与研发对齐，转化为可复用的业务知识和 Skill；产品出现后，业务问题进入受控、可验证、可继续钻探的工作流。证据线仍是产品段的核心视觉语言，但它服务于业务自主推进与过程可复核，而不是取代真实执行。

## 2. 规格

- 画幅：16:9。
- 工作母版：3840×2160，30fps，Rec.709。
- 交付版：1920×1080，30fps，H.264 High Profile，AAC。
- 总时长：90.0秒，不使用片尾黑场延长时长。
- 安全区：左右各8%，顶部7%，底部12%；重要 UI 与字幕不得进入底部10%。
- 产品录屏：保持原始比例，不裁掉导航、状态、版本或溯据关系所需上下文。

## 3. 色彩

| 角色 | 色值 | 用途 |
|---|---|---|
| 深海蓝 | `#0B1020` | 主背景、电影暗部 |
| 石板蓝 | `#132238` | 卡片、空间层次 |
| 证据青 | `#65D6D2` | 数据线、完成状态、核心强调 |
| 审批琥珀 | `#F6C453` | 用户确认、审批节点、注意信息 |
| 冷白 | `#E6EDF6` | 标题、正文、图表标签 |
| 警示红 | `#F87171` | 仅用于真实失败或风险提示，不作装饰 |

禁止霓虹彩虹渐变、赛博朋克紫粉、大片高饱和蓝光。青色只承担“证据连接”，琥珀色只承担“人的确认”。

## 4. 字体与文字

- 中文：PingFang SC；跨平台替代为 Source Han Sans SC / Microsoft YaHei UI。
- 英文和数字：Inter；代码与 Hash：JetBrains Mono。
- 标题字重：Semibold；正文：Regular；数字结论：Medium。
- 4K母版标题建议64—88px，正文36—44px，角标28—32px。
- 每屏只保留一个主句；字幕最多两行，每行不超过18个汉字。
- `#`、`Skill`、`SQL`、`Python`、`Artifact` 保留技术写法；旁白分别读作“井号”“Skill”“SQL”“Python”“Artifact”。

## 5. 构图与摄影

### 5.1 叙事镜头（S01—S08）

- 使用35mm、50mm、85mm三组等效焦段，浅景深但不虚化关键信息。
- 人物以侧面、背面和手部为主，避免数字人正面口型和表演不自然。
- 镜头运动以缓推、横移、轨道转正为主；单镜头只允许一种主运动。
- 角色空间真实、克制、无银行标识，不制造夸张“危机现场”。

### 5.2 产品镜头（S09—S19）

- 产品 UI 必须来自真实录屏；禁止用 Image Generation 或 HyperFrames 生成概念 UI。
- 2.5D摄像机只做5%—12%的平移/缩放，保持字体像素清晰。
- 鼠标动作前留0.25秒，点击后留0.4秒；关键状态至少完整可读1秒。
- `#`字段选择、Skill、计划、审批、工具状态、图表、版本和溯据卡均需保留上下文。
- 包装层不得覆盖输入框、字段列表、工具状态、图表标签、版本选择器和溯据表格。

## 6. 运动语言

- 核心动效：一条1.5—2px证据线在节点间流动，速度与旁白短句同步。
- 节点出现：180—260ms ease-out；节点连接：320—480ms cubic-bezier(0.2, 0.8, 0.2, 1)。
- 转场优先匹配切换、遮罩推移和8—12帧淡化；不使用模板化闪白、旋转或故障效果。
- Pain escalation 只通过任务入队、日历推进和静态报告无法承接新追问表现，不使用研发失误、数据错误或系统故障制造冲突。
- Product Reveal 后镜头稳定，运动精度高于运动幅度。
- 最后一帧静止24帧，让品牌与金句被记住。

## 7. 真实 UI 与生成素材边界

| 内容 | 允许方式 | 禁止方式 |
|---|---|---|
| 人物、办公室、抽象流程 | HyperFrames / Image Generation 后动画 | 出现真实银行标识或可识别客户信息 |
| 抽象证据线、标题、流程节点 | Remotion | 把动画节点伪装成真实工具结果 |
| 产品工作台 | 真实录屏 + Remotion 镜头包装 | 生成式概念 UI、静态稿冒充运行状态 |
| SQL/Python/审批 | 同一成功会话真实状态 | 手改文本、拼接不同会话 |
| 图表、报告、溯据卡 | 同一报告版本与执行链 | 重新绘制或生成不存在的业务结果 |
| Logo与品牌结尾 | 仓库真实品牌资产 + Remotion | 改写名称、临时增加未批准口号 |

## 8. 声音设计

- 声音：前36秒为三名角色的对白式旁白，之后由林主管第一人称接管；普通话、专业、克制、正常语速，不使用“播音腔式激昂”。
- 音乐：真实办公环境下的低频节拍开场，15秒后随排期与等待收紧，32秒后加入清晰和声，70秒结果出现时抬升，86秒收束。
- 音效：任务提醒、键盘、会议接通、任务卡入队、日历推进、细线连接、审批确认、任务完成；UI音效必须轻于旁白。
- 混音目标：整体约 -16 LUFS，真峰值不高于 -1 dBTP；旁白始终比音乐高6—10dB。
- 29—32秒音乐收窄，以落笔声突出业务知识沉淀；32—36秒由键盘与Skill完成声建立向产品段的声音桥。
- 86—90秒禁止额外提示音，保留金句与和声尾音。

## 9. 信息与业务边界

- 核心痛点：存续期业务人员不应为了每一次报表分析和后续钻探，都依赖科技研发人员重新沟通、排期和开发，也不应以熟练编写 SQL/Python 为使用前提。
- 产品定位：面向银行存续期业务的可验证、可对话数据分析智能体；业务人员以业务语言发起任务，经用户确认后调用受控 SQL/Python 工具链，得到真实、可复核、可继续钻探加工的版本化报告。
- “自主”指业务人员可自行发起、确认、追问和组织报告，不表示绕过数据权限、开发治理、工具边界或人工审批。
- 不使用“无需研发”“替代科技”“零等待”等绝对宣传；准确表达为减少逐次报表需求沟通与功能开发排期依赖，释放科技支持压力。
- 只展示数据中已有的风险分类事实，不生成新的风险信号、评级或处置建议。
- 不表述为“自动判断风险”“替代业务人员”“无需审批”。
- 演示使用脱敏 CSV；不得出现客户姓名、账号、密钥、用户名、绝对路径或通知。
- 加速真实等待过程时必须持续显示“真实工具执行，等待过程已加速”。
- 收尾固定为：**让每份报告有据可溯，让每次分析沉淀为能力。**

## 10. Look-dev 门禁

批量生成前按两级门禁制作五个代表镜头：

1. 叙事门禁：S01检验真实办公环境、任务提醒、时间压力和人物质感；S05检验“一次性交付后出现新问题”的自然表演；S08检验业务知识向受控Skill封装的因果转折。
2. 产品门禁：S09检验品牌揭示和匹配切换；S13检验真实 UI 清晰度、审批琥珀色和证据青的平衡。

五个镜头同时通过人物连续性、办公真实性、色彩、字体、UI清晰度、运动节奏和业务边界审查后，才允许批量生成或合成其余镜头。
