# Storyboard 与成片 QA 门禁

## G0｜故事与范围

- [ ] 总时长精确90.0秒，镜头连续、无重叠、无空洞。
- [ ] 11个段落与 `presentation-video.md` 时间结构一致。
- [ ] 15秒内理解主角、临时任务和“业务懂问题但无法独立完成数据报告”的矛盾，40秒前完成产品揭示。
- [ ] 15—29秒清晰呈现研发排期、一次性报表和新增追问；29—36秒完成业务知识沉淀与研发Skill封装。
- [ ] 只讲一个核心判断：业务人员不直接编写 SQL/Python，也能自主推进一条经确认、真实执行、可复核、可继续钻探的受控分析链。
- [ ] 不把研发人员塑造成阻碍，不把“减少逐次报表开发依赖”夸大为“无需研发或数据治理”。
- [ ] 未暗示系统自动作出风险判断或处置决定。

## G1｜Look-dev

- [ ] S01、S05、S07、S08通过人物连续性、办公真实性、冲突递进和知识封装转折审查。
- [ ] S09使用真实品牌资产，能自然匹配切入真实工作台。
- [ ] S13真实UI在4K母版和1080p交付版均清晰。
- [ ] 青色只表示证据/完成，琥珀色只表示人的审批。
- [ ] 五个代表镜头通过后再批量生产。

## G2｜产品真实性

- [ ] S10真实键入`#`并从列表选择三个字段。
- [ ] S11真实选择“整体风险分类分布分析报告”Skill。
- [ ] S12计划顺序与真实工具链一致。
- [ ] S13包含待审批、批准、running、completed和Dataset。
- [ ] S14证明Python只消费上游受控结果。
- [ ] S15—S18来自同一成功会话和同一报告链。
- [ ] S17证明追问基于同一会话已有结果生成版本2，而非新的静态报表开发。
- [ ] 报告版本1/2、图表和溯据卡内容一致。
- [ ] 加速真实等待过程时持续显示加速说明。
- [ ] 无用户名、客户名称、账号、密钥、绝对路径或通知。

## G3｜叙事与画面

- [ ] 前32秒无概念产品UI；S08的Skill构建界面仅作知识封装剧情道具，不冒充真实执行状态。
- [ ] 每个产品卖点均有可见动作证明。
- [ ] 生成式人物无Logo、无敏感数据、无异常手部或口型。
- [ ] 转场服务因果关系，不使用模板化炫技效果。
- [ ] 关键产品状态至少完整可读1秒；图表至少3秒。
- [ ] 字幕、角标和摄像机运动不遮挡交互及数据。

## G4｜声音与字幕

- [ ] 旁白正常语速、专业、自然，无强行加速。
- [ ] S07落笔声清楚、S08两名角色的声音桥自然；S09产品名清楚；S19—S20金句连续、完整。
- [ ] 字幕最多两行，每行不超过18个汉字。
- [ ] 技术词与产品词拼写统一。
- [ ] 音乐、音效有明确授权或为原创。
- [ ] 混音约 -16 LUFS，真峰值不高于 -1 dBTP。

## G5｜技术交付

- [ ] 3840×2160母版和1920×1080提交版均为16:9、30fps。
- [ ] 视频H.264 High Profile，音频AAC，音画完整同步。
- [ ] 90.0秒成片可完整解码，无黑帧、冻结、断音或丢帧。
- [ ] 在另一台电脑完整播放通过。
- [ ] 输出SHA-256、素材清单、版本记录和最终验收记录。

## 失败处理

- 产品状态不稳定：使用同一成功会话的审定素材，不跨会话拼接。
- 生成素材风格漂移：回到 S01 look-dev，不在后期用重滤镜补救。
- 字幕遮挡产品：优先缩小/移动字幕带，不裁切或拉伸产品画面。
- 旁白超时：精简旁白，不加速到不自然。
- 溯据信息不可读：延长S18或从S19借时，不能只靠旁白声称。
- 任何真实执行失败：保留失败状态并停止该链路，不伪造成功镜头。
