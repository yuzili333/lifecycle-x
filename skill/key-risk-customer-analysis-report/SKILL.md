# 重点风险客户分析报告

## 目标

依据用户所选数据源生成“重点风险客户分析（含金额占比）”报告。重点风险客户指最新风险分类为关注或不良的合同记录。不得复制模板示例值、企业名称或示例结论，不得使用固定物理字段映射、表字典或数据源中不存在的字段。

## 字段绑定

核心业务角色：

- 客户名称
- 最新风险分类
- 贷款余额

辅助业务角色：

- 合同流水号
- 一级分行
- 客户所属省/市
- 年初风险分类
- 最新风险分类结果
- 主要担保方式名称
- 国标行业投向名称
- 业务品种名称
- 短中长期贷款标识
- 合同金额

业务角色使用以下明确含义：

- “省份”对应当前数据源中的真实字段“客户所属省/市”。
- “行业”对应当前数据源中的真实字段“国标行业投向名称”。

按以下顺序绑定真实字段：

1. 优先采用用户通过 `#` 选择且客户端确认有效的字段。
2. 其次在当前数据源真实 Schema 中匹配模板业务名称。
3. 精确名称不存在时，根据真实字段名称、字段类型和脱敏样例值推荐候选。
4. 候选字段必须通过本地存在性和类型校验。
5. 多个候选无法唯一确定时，展示真实候选名称并请求用户确认。

核心角色任一缺失时，不生成不完整报告。辅助字段缺失时，表头使用模板中的业务角色名称，单元格展示 `--`，同时用一句数据质量说明披露，不得猜测、使用其他字段替代或输出未解析的模板占位符。

表字典、业务字段 ID、历史英文别名和物理字段后缀均不是必要条件。数据源真实 Schema 是字段存在性的唯一依据。

## 风险分类

使用实际分类值归并：

- 正常：值明确表示正常，且不是“非正常”。
- 关注：值明确表示关注。
- 不良：值为不良，或明确表示次级、可疑、损失。
- 非正常：关注与不良合计。

若最新风险分类只有次级、可疑、损失等细分类，可直接归入不良。若出现只能识别为“非正常”但无法区分关注或不良的值，必须列出真实值请求用户确认，禁止自行拆分。

最新风险分类结果只用于明细展示和关注、不良内部子类统计，不得覆盖最新风险分类字段。年初风险分类只用于风险迁徙分析。

## 合同笔数与明细粒度

报告中的“笔数”表示合同笔数，风险客户表每行对应一笔合同：

1. 合同流水号存在，且所有有效记录均有非空稳定值时，按合同流水号去重。
2. 同一合同流水号的客户、分类、金额及已选辅助字段一致时合并为一笔，金额只统计一次。
3. 合同流水号缺失、存在空值，或同一流水号的报告字段发生冲突时，整份报告统一降级为有效记录行数。
4. 有效记录必须具有可识别的客户名称、最新风险分类和可解析的贷款余额。
5. 同一客户存在多笔合同时不合并为一个客户；除非用户明确要求客户级汇总。

Python 结果必须包含：

- `countBasis`: `contract_serial` 或 `valid_rows`
- `countBasisField`
- `fallbackReason`
- `deduplicatedRecordCount`
- `excludedRecordCount`

报告必须写明实际笔数口径。降级时说明具体原因，不输出内部错误。

## 金额和占比

- 默认金额指标为贷款余额；合同金额只用于风险客户明细表。
- 只根据真实字段名称或 Schema 单位识别元、万、万元、亿、亿元，支持中英文括号。
- 表格金额统一展示为万：元除以 `10,000`，万或万元保持不变，亿或亿元乘以 `10,000`。
- 单位无法确认时请求用户确认，不根据字段后缀或数值大小猜测。
- 金额清洗、去重、分类、累计、换算和对账全部使用 `Decimal`；笔数、行数等整数计算占比时也必须使用 `Decimal(count) / Decimal(total)`，禁止整数直接相除产生 `float`。完成对账前禁止转换为 `float`。
- 贷款余额总额、非正常余额、关注余额和不良余额均使用同一合同粒度。
- 非正常笔数占比 = 非正常合同笔数 / 全样本有效合同笔数。
- 非正常贷款余额占比 = 非正常贷款余额 / 全样本贷款余额。
- 每笔风险客户“占总额%” = 该合同贷款余额 / 全样本贷款余额。
- 分母为零时占比为 `null`，报告展示 `--`。
- 百分比固定保留两位小数。
- 金额小于 `10,000万` 时展示为带千分位的万元；大于等于 `10,000万` 时按 `10,000万 = 1亿` 换算为亿元并保留两位小数。使用 `ROUND_HALF_UP`，不添加“约”。

## 工具流程

执行三个串行步骤：

1. SQL 查询：查询用户筛选范围内的全样本明细，不得先按最新风险分类过滤。读取核心字段和真实存在的辅助字段；禁止 `LIMIT`、`GROUP BY`、聚合函数或 `DISTINCT` 完成最终统计。
2. Python 分析：只读取完整 Workflow Dataset 的 `rows`，按合同口径处理全样本，再筛选关注及不良记录；计算笔数、金额、全样本占比、风险迁徙、明细排序和特征结论数据。
3. 生成报告：严格依据完整 Python 结果和报告模板生成 Markdown，不重新计算、不补写数据源中不存在的属性。

SQL 必须保留全样本，因为全样本合同笔数和贷款余额是所有占比的分母。Python 不得从提示词预览、样例行或模型记忆中构造记录。

## Python 数据闭环校验

输出 JSON 前必须完成以下本地确定性校验：

1. `sampleCount` 等于最终合同口径下的全样本有效记录数。
2. `nonNormalCount = attentionCount + nonperformingCount`。
3. `nonNormalCount` 等于 `riskCustomers.length`。
4. `nonNormalLoanBalance = attentionLoanBalance + nonperformingLoanBalance`。
5. 风险客户逐行贷款余额合计等于 `nonNormalLoanBalance`。
6. 每行占总额比例均使用 `sampleLoanBalance` 作为分母。
7. 风险客户序号从 1 开始连续，且每行客户名称和分类来自同一条清洗后合同记录。
8. 年初正常转最新非正常的劣变笔数只能从同时具备两个分类字段的真实记录计算。

任一校验失败时抛出包含具体差异的异常，不输出部分统计结果，也不进入报告生成。

## 排序与特征结论

风险客户表稳定排序：

1. 不良类优先于关注类。
2. 同类按贷款余额降序。
3. 贷款余额相同时按客户名称升序。

“重点风险客户特征分析”最多输出五条编号结论：

1. 分析业务品种和期限组合。仅在全部风险合同属于同一组合时使用“全部”；否则列出真实主要组合及笔数、余额和占比。
2. 列示不良合同的客户名称、分行、担保方式、行业和贷款余额；无不良时明确说明。
3. 汇总关注类的最新风险分类结果分布；字段缺失时只说明关注总笔数和余额。
4. 分析年初到最新分类的迁徙，包括正常转非正常、关注维持、改善和劣变；年初字段缺失时省略。
5. 说明风险客户实际涉及的分行数、行业数和省份数，并按合同笔数或贷款余额识别集中项。“省份”只能来自真实字段“客户所属省/市”，“行业”只能来自真实字段“国标行业投向名称”。未绑定真实“客户所属省/市”字段时禁止输出省份数量，也不得根据分行名称、客户名称或地址文本推断省份；无法可靠归并行业门类时使用真实行业名称，不自行创造行业大类。

所有结论必须从结构化统计结果生成。模板示例中的数字和结论不得复用。不得输出授信审批、风险分类调整或风险处置决定。

## 报告约束

- 标题为 `{数据源表名或无后缀文件名}分析报告`。
- 主章节固定为“重点风险客户分析（含金额占比）”。
- 摘要依次展示全样本笔数、非正常笔数及占比、不良和关注笔数。
- 金额维度展示非正常、关注、不良贷款余额及占全样本贷款余额比例；具备年初分类时追加正常转非正常的劣变笔数。
- 表格包含全部且仅有的非正常合同，禁止 Top N 截断或加入正常类记录。
- 表格列顺序严格匹配模板，缺失辅助值展示 `--`。
- 特征分析只输出上述编号结论，不新增图表、核心指标、风险建议或其他模板外章节。
- 不输出内部 Artifact ID、工具名称、脚本、本地路径、HTML、临时文件或模板占位符。
- 不生成溯据卡；系统根据真实工具记录追加。
