# 各分行资产质量状况分析报告

## 目标

依据用户选择的数据源生成“各分行资产质量状况（笔数+金额）”报告。不得使用模板示例值、模拟数据、固定英文映射、表字典或数据源中不存在的字段。

## 字段绑定

业务角色：

- 一级分行
- 最新风险五级分类
- 金额指标（默认贷款余额）
- 合同流水号（可选，用于合同笔数去重）

绑定顺序：

1. 优先采用用户通过 `#` 选择且客户端已确认存在的字段。
2. 其次在当前数据源真实 Schema 中匹配模板业务名称。
3. 精确名称不存在时，根据真实字段名称、类型和脱敏样例值推荐候选。
4. 候选必须通过本地字段存在性和类型校验。
5. 多个候选无法唯一确定时，展示真实候选名称并请求用户确认。

表字典和业务字段 ID 只能作为可选说明，不能作为执行前提。不得根据历史物理字段、后缀或数值大小猜测字段与单位。

金额指标按以下优先级确定：

1. 用户通过 `#` 选择或在需求中明确指定金额字段时，使用该真实字段。
2. 用户未指定时，默认金额指标为贷款余额，报告展示单位为 `万`。
3. 默认匹配业务名称为“贷款余额”的真实字段，优先采用字段名称或 Schema 明确标注为万、万元的字段。
4. 源单位为元时除以 `10,000`，源单位为万或万元时保持数值，源单位为亿或亿元时乘以 `10,000`，统一转换为万后再统计。
5. 用户明确指定其他金额指标或展示单位时，以用户选择为准，并在表头及金额比率列使用该指标的真实业务名称和单位。
6. 单位无法从真实字段名称或 Schema 确认时，不猜测换算关系，应展示真实候选字段并请求用户确认。

缺少一级分行、五级分类或选定金额指标任一必需角色时，不生成不完整报告；应基于当前 Schema 返回真实候选字段。分行空值和无法识别分类的记录从标准统计中排除并计入数据质量说明。

## 分类与笔数

五级分类归并：

- 正常：正常。
- 关注：关注。
- 不良：源值“不良”，或次级、可疑、损失合计。

不得用只有“正常、关注、不良”粒度的数据反向拆分次级、可疑和损失。

合同笔数优先按合同流水号去重：

1. 合同流水号在所有有效业务记录中非空且稳定时，按合同流水号去重。
2. 同一合同流水号的分行、五级分类和选定金额指标一致时合并为一笔，金额只统计一次。
3. 合同流水号缺失、存在空值或同一流水号口径冲突时，整份报告统一降级为有效记录行数。
4. 有效记录是分行、分类均可识别且选定金额可解析的业务记录；完全空行和解析失败行不计入。

报告必须显示实际口径：

- `笔数口径：按合同流水号去重`
- 或 `笔数口径：按有效记录行数统计（合同流水号不可用）`

## 金额与比率

- 只根据真实字段名称或 Schema 单位识别金额单位，支持元、万、万元、亿、亿元及中英文括号。
- 默认金额指标为贷款余额并统一换算为万；`万元` 的表头标签规范化为 `万`。
- 用户明确指定其他金额指标或展示单位时，按其要求进行可验证的确定性换算；未指定目标单位时保留该字段已确认的源单位。
- 四个金额列表头只显示分类和单位，例如 `正常(万)`，不得再次嵌入“贷款余额”等业务名称。
- 两组比率列的标题均依次使用 `不良率%`、`关注率%`：前一组表示笔数比率，表格末尾一组表示金额比率。不得在末两列表头增加“贷款余额”“万元”或其他金额指标前缀。
- 金额使用 `Decimal` 累计；不得用二进制浮点值直接累计业务金额。
- 表格金额使用千分位，最多保留源数据有效的小数位；不得改变合计精度。
- 金额清洗、分类汇总、分行汇总、全行汇总和对账必须始终使用 `Decimal`；所有对账完成前禁止转换为 `float`。
- `float` 仅允许在对账成功后用于最终 JSON 数值字段序列化；禁止从 `branchDistribution` 中已序列化的浮点金额反向构造 `Decimal` 做对账。
- 笔数不良率 = 不良笔数 / 分行合计笔数 × 100。
- 笔数关注率 = 关注笔数 / 分行合计笔数 × 100。
- 金额不良率 = 不良类金额 / 分行金额合计 × 100。
- 金额关注率 = 关注类金额 / 分行金额合计 × 100。
- 比率表格固定保留两位小数，不附加额外 `%` 字符，因为列标题已包含 `%`。
- 分行金额合计为零时，金额不良率和关注率为 `null`，表格展示 `--`，禁止展示虚假的 `0.00`。
- 全行平均率必须使用全量分子除以全量分母计算，禁止对各分行率做算术平均。

## 工具流程

执行三个串行步骤：

1. SQL 查询：读取用户筛选范围内全部明细行的一级分行、五级分类、选定金额指标和可用的合同流水号；禁止添加 `LIMIT`，禁止使用聚合函数、`GROUP BY` 或 `DISTINCT` 完成最终统计。
2. Python 分析：只从标准输入中的完整 `rows` 读取 SQL 数据集，禁止读取提示词内的预览行、样例行或自行构造记录；先按已确认单位将金额转换到报告展示单位，再确定笔数口径，按分行归并正常、关注、不良，计算笔数、金额、四类比率、全行加权平均和结论所需排序；为每个金额和比率生成报告可直接使用的展示字符串后输出结构化 JSON。
3. 生成报告：严格使用报告模板和完整 Python 结果生成 Markdown，逐项渲染 `branchDistribution` 的全部分行，不自行增加、删减或补齐分行、图表、指标或分析章节。

SQL 只负责读取与筛选，Python 负责全部去重、分组、统计、占比、排序和结论数据准备。

## Python 数据闭环校验

Python 脚本必须在输出 JSON 前完成以下本地确定性校验；任一条件不成立时抛出包含具体差异的异常，不得输出部分结果，也不得进入报告生成：

1. 有效行的分行、分类、选定金额指标和合同流水号必须作为同一条记录同步清洗、单位换算和去重，禁止分别提取列后按位置重新拼接。
2. `distinctBranchCount` 等于采用最终笔数口径后真实记录中的非空分行去重数。
3. `branchDistribution` 对每个真实分行只生成一行，行数必须等于 `distinctBranchCount`；禁止只保留前 5、前 10 或其他 Top N 分行。
4. 每个分行的 `totalCount` 必须等于该分行 `normalCount + attentionCount + nonperformingCount`，且只能从该分行记录计算。
5. 所有分行 `totalCount` 之和必须等于 `overall.totalCount`，并等于 `deduplicatedRecordCount`；禁止把 `overall.totalCount` 或全量输入行数复制为任一分行的 `totalCount`。
6. 每个分行的 `totalBalance` 必须在内部 `Decimal` 数据结构中等于该分行三类金额之和；所有分行金额合计必须使用 `sum(decimal_values, Decimal("0"))` 与全行对应金额逐项精确对账。禁止使用 `sum(branch["totalBalance"])`、`Decimal(str(float_value))` 或任何已序列化浮点字段进行金额校验。为兼容现有报告数据协议，`normalBalance`、`attentionBalance`、`nonperformingBalance`、`totalBalance` 及对应展示字段承载本轮选定的金额指标。
7. `branchDistribution` 中的分行名称集合必须与最终有效记录中的真实分行集合完全一致，不得生成数据源中不存在的分行名称。
8. 输出 `validation` 对象，记录分行数、分行表行数、分行笔数合计、全行笔数以及分行、笔数、金额三项对账状态；只有三项状态均为 `true` 才允许输出结果。

报告模型不得重新统计原始数据。报告表中每个分行名称和数值必须来自 `branchDistribution` 对应项，`overall` 只用于全行结论和对账，禁止作为分行表格行复用。

全行笔数及金额比率的分子必须使用所有分行对应分类的合计值，禁止读取 `branchDistribution[0]` 或任一单个分行作为全行分子。比率数值字段使用 `0..1` 小数，展示字段必须乘以 100 后保留两位小数。

## 排序与结论

表格按以下顺序稳定排序：

1. 笔数不良率降序。
2. 金额不良率降序。
3. 笔数关注率降序。
4. 金额合计降序。
5. 分行名称升序。

“分析结论”仅根据真实统计结果生成，采用编号段落：

1. 列出存在不良贷款的分行，优先说明不良笔数、不良率、金额不良率及其相对全行平均水平；无不良时明确说明。
2. 列出关注率显著集中的分行，尤其是关注率不低于 50% 或唯一/少量样本集中为关注类的分行；没有时省略。
3. 列出其余存在关注类贷款、需持续观察劣变趋势的分行；不得与上一条重复。
4. 从选定金额指标规模靠前且关注、不良笔数均为零的分行中最多列出 5 家作为稳健分行；没有满足条件的分行时省略。

禁止使用固定分行数量阈值判断“头部”。稳健分行应先按金额合计降序，再从真实结果中选取。不得输出授信审批、风险分类调整或风险处置决定。

## 报告约束

- 标题为 `{数据源表名或无后缀文件名}分析报告`。
- 主章节为“各分行资产质量状况（笔数+金额）”。
- 表格列顺序、笔数和金额双维度与模板一致。
- 表格必须包含 `branchDistribution` 中全部且仅有的真实分行，每个分行恰好出现一次；禁止输出全行合计作为分行行，禁止截断为 Top N。
- 报告默认设置 `amount_unit_label=万`；用户明确指定其他金额指标或单位时使用经确认的真实字段及单位完成统计，但末两列标题仍固定为 `不良率%`、`关注率%`。
- `amount_unit_label` 只包含单位文字，不含括号、斜杠或业务名称；四个金额列表头必须渲染为 `正常({{amount_unit_label}})`、`关注({{amount_unit_label}})`、`不良({{amount_unit_label}})`、`合计({{amount_unit_label}})`。
- 表格第 6、7 列分别渲染笔数不良率和笔数关注率，第 12、13 列分别渲染金额不良率和金额关注率；不得因标题相同而复用或错置比率值。
- 分析结论只包含上述编号段落，不增加图表、核心指标、数据质量章节或其他模板外内容。
- 数据质量问题只在统计口径之后用一句简短文字说明；无问题时不展示。
- 不输出内部 Artifact ID、工具名称、脚本、本地路径、HTML、临时文件或模板占位符。
- 不生成溯据卡；系统根据真实工具记录追加。
