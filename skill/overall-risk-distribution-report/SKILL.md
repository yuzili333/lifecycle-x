# 整体风险分类分布分析报告

## 目标

严格依据用户所选数据源和当前会话 Artifact，生成“整体风险分类分布（笔数+金额）”报告。不得使用示例数值、模拟数据、历史物理字段映射或数据源中不存在的字段。

## 字段解析

业务角色仅包括：

- 合同流水号
- 最新风险五级分类
- 最新风险分类结果
- 贷款余额
- 合同金额

按以下顺序绑定真实字段：

1. 优先使用用户通过 `#` 选择且客户端确认有效的字段。
2. 其次在当前数据源 Schema 中匹配报告模板的字段语义。
3. 精确名称不存在时，根据真实字段名称、字段类型和脱敏样例值推荐候选字段。
4. 候选字段必须经过本地存在性和类型校验。
5. 多个候选无法唯一确定时，列出真实候选名称并请求用户确认。

表字典、业务字段 ID、固定英文别名和物理字段后缀均不是字段识别条件。不得猜测不存在的字段。

“贷款余额”与包含明确单位的“贷款余额(万元)”或“贷款余额（万元）”属于同一业务角色。语义识别时分离业务名称与单位，生成 SQL、Python 时始终使用实际字段名。若数据源同时存在多个相近字段且用户未明确选择，不得自动合并。

若不存在可用的最新风险五级分类字段，但最新风险分类结果的实际值足以识别类别，可按值归并：

- 正常类明细归入正常。
- 关注类明细归入关注。
- 次级、可疑、损失分别归入对应五级分类。

不得用只有“正常、关注、不良”粒度的字段拆分次级、可疑和损失。

## 合同笔数

优先按合同流水号去重：

1. 合同流水号字段存在，且所有有效业务记录均有非空稳定值时，按合同流水号去重。
2. 同一合同流水号的分类、贷款余额及存在时的合同金额一致，可合并为一笔，金额只统计一次。
3. 未找到字段、字段全部为空、有效记录存在空值，或同一流水号存在分类或金额冲突时，合同口径判定失败。
4. 合同口径失败后，整份报告统一使用有效记录行数，笔数和金额均保持同一数据粒度。
5. 有效记录是满足用户筛选条件且具有可识别分类的业务记录；完全空行和解析失败行不计入笔数。

Python 分析结果必须包含：

- `countBasis`: `contract_serial` 或 `valid_rows`
- `countBasisField`: 实际使用的合同流水号字段；降级时可为空
- `fallbackReason`: 降级原因；未降级时为空
- `deduplicatedRecordCount`
- `excludedRecordCount`

报告摘要必须写明“笔数口径：按合同流水号去重”或“笔数口径：按有效记录行数统计（合同流水号不可用）”。降级时补充简短、具体的原因。

## 金额单位

- 只根据实际字段名称或 Schema 单位信息识别元、万元、亿元等单位，支持中英文括号。
- 不根据物理字段后缀、数值大小或历史约定猜测单位。
- 计算过程保留源字段单位；表格保留实际字段名称和单位。
- 分析文字使用去除单位后的业务名称“贷款余额”。
- 源单位为元时按 `100,000,000元 = 1亿元` 换算，源单位为万元时按 `10,000万元 = 1亿元` 换算，源单位为亿元时保持数值；表格继续保留源字段单位，报告文字中的金额统一展示为亿元。
- 金额一旦解析为 `Decimal`，分类金额、累计合计、占比的分子和分母、万元到亿元换算都必须保持 `Decimal`；禁止先把分类金额转换为 `float` 后再除以 `Decimal` 合计值。金额占比应先执行 `Decimal / Decimal`，只在最终 JSON 序列化时转换为 `float`。
- 亿元展示值统一使用 `Decimal.quantize(Decimal("0.001"), rounding=ROUND_HALF_UP)`，并固定保留小数点后三位，例如 `10,000万元` 展示为 `1.000亿元`，`373,780.35万元` 展示为 `37.378亿元`，`765,794.84万元` 展示为 `76.579亿元`。
- 固定三位是本报告的展示精度，换算结果前不添加“约”；禁止输出超过三位小数或删除末尾的零。
- Python 分析结果中的总计、五级分类和分类结果明细均必须分别保存亿元数值与固定三位展示字符串。报告生成阶段不得再次从表格字符串计算或格式化金额。
- 单位不明确时仍可计算金额占比，但不得把金额总计标注为万元或亿元。
- 合同去重成功时金额按去重合同统计；降级时金额按有效记录行统计。

## 工具流程

默认规划五个串行步骤：

1. SQL 查询：读取用户筛选范围内的明细字段，不使用 `GROUP BY`、聚合函数或 `DISTINCT` 完成最终统计；当前 Schema 存在合同金额字段时必须一并查询，只有真实字段不存在时才能省略。
2. Python 分析：校验合同流水号，确定计数口径，计算分类笔数、笔数占比、贷款余额和金额占比；`totals`、`fiveLevelDistribution` 和 `riskResultDistribution` 中每个金额项都必须包含源单位数值、`loanBalanceInYi` 及固定三位的 `loanBalanceDisplay`。`totals.contractAmountDisplay` 同样固定三位，并生成带业务标签和标点的 `contractAmountClause`。脚本必须保持简洁且语法完整，所有真实字段名称必须从上游结果字段清单逐字符复制；字段名称中的中英文括号和单位必须完整包含在字符串引号内，禁止手工改写或输出推测性长注释。
3. 绘制图表：生成“最新风险五级分类笔数分布”饼图，`chartType` 使用 `pie`，维度字段使用 Python Artifact 的 `category`，指标字段使用 `count`；维度标签使用“最新风险五级分类”，指标标签使用“笔数”，每个扇面必须可见展示该分类笔数与占总笔数比例。
4. 绘制图表：生成“最新风险五级分类贷款余额分布”纵向柱状图，`chartType` 使用 `bar`，维度字段使用 Python Artifact 的 `category`，指标字段使用 `loanBalance`；维度标签使用“最新风险五级分类”。真实源单位确认为万元时，指标标签和 Y 轴标题统一使用“贷款余额（万元）”，Y 轴显示数值刻度；其他已确认单位继续保留真实源单位，不得猜测或换写单位。
5. 生成报告：始终以成功的 SQL/Python 分析结果生成完整 Markdown；只引用本轮成功生成的图表 Artifact。

两张图表均依赖同一个 Python 分析结果，但图表属于报告的可选展示，不是报告生成的阻塞依赖。任一图表失败时继续生成报告，只省略失败图表；两张图表均失败时删除整个“可视化图表”章节。禁止引用历史轮次图表补位。不得把 SQL 聚合结果再按聚合行数进行二次计数。

## 统计规则

- 默认使用所选数据源的全部日期范围，除非用户明确给出筛选条件。
- 五级分类按正常、关注、次级、可疑、损失排序；缺失类别显示零。
- 不良类为次级、可疑、损失合计。
- 笔数占比分母采用最终选定计数口径下的有效总笔数。
- 金额占比分母采用相同数据粒度下的有效贷款余额合计。
- 空值和无法识别的分类单独记录为数据质量问题，不归入标准分类。
- 合同金额只在真实字段存在且单位可解释时用于摘要，不替代贷款余额。

缺少贷款余额字段时，不生成伪造的完整报告；应说明缺少的业务角色并推荐当前 Schema 中真实存在的候选字段。缺少最新风险分类结果时，可以生成五级分类主表，但省略明细表和“正常类内部细分”。缺少合同金额时只省略摘要中的合同金额。

## 报告约束

严格使用声明的报告模板：

- 标题由系统规范化为 `{数据源表名或无后缀文件名}分析报告`。
- 主体包含整体风险分类分布、五级分类表、分类结果明细和分析结论；“可视化图表”章节仅在本轮至少一张图表成功时展示。
- 分析结论仅包含 `【笔数维度】`、`【金额维度】`、`正常类内部细分`。
- 正常类内部细分只能使用真实分类结果；缺失时省略，不推测。
- 不输出示例数值、内部 Artifact ID、工具名称、本地路径、HTML 图片、临时文件或额外风险建议。
- 摘要必须分别显示业务标签：`` `贷款余额`合计 {{loan_balance_display}}``；存在合同金额时必须使用完整子句 ``，`合同金额`合计 {{contract_amount_display}}。``，不得只拼接金额值。
- `【金额维度】` 中的总计、正常、关注、次级、可疑、损失及不良类合计金额，必须直接引用对应统计项的 `loanBalanceDisplay`，统一显示三位小数的亿元值；不得展示万元原值。
- `正常类内部细分` 中正常1、正常2、正常3等每个明细金额也必须直接引用 `riskResultDistribution[].loanBalanceDisplay`，统一显示三位小数的亿元值；不得展示万元原值。
- 表格仍使用真实贷款余额字段名称和源单位数值，不应用亿元展示字符串替换表格金额。
- 不生成溯据卡；系统根据真实工具记录追加。
