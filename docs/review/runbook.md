# 运行说明与 Golden Path

## 1. 启动和登录

1. 完成[部署步骤](deployment.md)后运行 `pnpm dev`。
2. 使用账号 `analyst`、密码 `Lifecycle@123` 登录。该凭据只用于本地演示。
3. 在“设置 → 模型配置”填写评委自己的 SiliconFlow API Key、推理模型和执行模型。
4. 返回“数据助手”，创建干净会话。

## 2. 导入脱敏数据

1. 在输入区上传 `de-identified-data/信贷风险.csv`。
2. 等待 CSV 状态变为可用，不在导入过程中发送任务。
3. 确认当前会话选择的是该 CSV。

演示文件包含200条脱敏记录。它只用于比赛验证，不代表生产数据或生产统计口径。

## 3. 显式选择字段和 Skill

1. 在输入框键入 `#`，确认弹出当前 CSV 的真实字段列表。
2. 从列表依次选择：
   - `最新风险五级分类`
   - `贷款余额(万元)`
   - `合同流水号`
3. 选择 Skill“整体风险分类分布分析报告”。
4. 发送以下任务；三个 `#字段名` 必须由字段列表点击生成，不能手工伪造：

> 基于 #最新风险五级分类、#贷款余额(万元) 和 #合同流水号，分析整体风险分类的笔数和贷款余额分布，生成图表和分析报告。

`#` 用于显式确认重点字段、减少歧义，不表示 Agent 永远不能读取 Skill 所需且已授权的其他字段。

## 4. 审批和执行

1. 查看 Agent 给出的查询、统计、绘图和报告计划。
2. SQL 进入待审批状态后检查脚本并批准。
3. 确认 SQL 只读执行并产生 Workflow Dataset。
4. Python 进入待审批状态后检查脚本并批准。
5. 确认 Python 读取上游数据集，而不是直连业务数据库。
6. 等待图表、首版报告和溯据卡完成。

基准演示数据的核验参考是200笔记录、贷款余额合计373,780.35万元；如果结果不同，应停止演示并检查数据文件、字段选择和执行日志，不修改报告去迎合参考值。

## 5. 多轮追问和版本

在同一会话发送：

> 只看正常类内部细分，按贷款余额降序，并基于刚才的分析结果重新生成报告。

核验：

- 追问引用本会话已有 Tool/Artifact，而不是只复述聊天文本。
- 生成报告版本2，并保留版本1。
- 图表、报告与溯据卡来自同一执行链。
- 溯据卡能展示数据来源、字段范围、工具执行和上下游关系。

若数据不支持正常类内部细分，可使用已验证备选追问：

> 按贷款余额降序重新展示五级分类，并基于刚才的结果生成新版报告。

## 6. 导出验收

从当前报告版本分别导出 PDF、DOCX 和 Markdown，并实际打开三个文件。检查标题、表格、图表、金额单位、版本内容和溯据信息；导出失败时保留错误信息，不用其他会话或手工文件替换。

## 7. 结束

退出 Electron 后在终端按 `Ctrl+C`。再次执行 `pnpm doctor`，确认环境仍正常且认证服务没有被异常进程占用。
