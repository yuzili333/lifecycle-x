# 原创性与第三方依赖说明

## 原创实现范围

本源码包中与参赛作品直接相关的实现包括：自然语言到受控工具计划、审批状态、SQL/Python 执行衔接、Workflow Dataset、Artifact 血缘、`#`字段引用、领域 Skill、图表、版本化报告、溯据卡和多格式导出。

源码提交历史、任务记录和赛事报名材料共同构成时间与作者证据。本文不把第三方框架、通用模板或赛事前已有的基础工程能力表述为比赛期间原创成果；如组委会要求按比赛周期进一步拆分，应以 Git 提交和正式申报口径为准。

## 第三方依赖

项目使用 Electron、React、TypeScript、Vite、Express、SQLite 相关组件、DOCX 生成库、Astryx UI 组件及其他 npm 依赖。它们用于桌面运行、界面、构建、服务和文档导出，不等同于“溯据”的业务工作流与证据链实现。

`pnpm submission:package` 会依据锁文件生成去除本机绝对路径的 `THIRD_PARTY_LICENSES.json`，随源码包一并交付。依赖名称、版本、许可证和主页以该文件及 `pnpm-lock.yaml` 为准。

## 数据、模型和外部服务

- 演示 CSV 为脱敏验证数据，不宣称为真实客户或生产数据。
- 模型能力来自评委自行配置的 SiliconFlow API 和相应模型；模型本身不属于参赛团队原创。
- 项目不附带 API Key、模型输出录制回放或伪造工具结果。
- 源码包不包含其他已投产项目、第三方完整产品源码、视频剪辑工程或未经授权素材。

## 评审边界

可复核的技术原创点应落在“计划—审批—真实工具执行—Artifact—报告—溯据”闭环，而不是依赖数量或模型品牌。若现场网络或模型服务不可用，应展示已提交源码、架构、测试和真实演示视频，不把静态兜底材料冒充现场执行。
