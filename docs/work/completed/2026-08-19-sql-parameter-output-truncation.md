# Task: SQL Parameter Output Truncation

- Status: completed
- Owner: human + agent
- Started: 2026-08-19

## Goal

Prevent SQL tool parameter generation from exhausting the model output limit and recover once with a compact model-generated SQL parameter.

## Scope

- Audit the latest model/tool logs and persisted Agent Run.
- Restore stage-scoped built-in Skill SQL parameter instructions when a verified SQL skeleton exists.
- Tighten the generic SQL tool parameter contract against explanation/schema/repetition inside the `sql` value.
- Add one provider-truncation retry using the reasoning model without local deterministic SQL fallback.

## Non-goals

- Do not increase SQL output tokens without evidence of a legitimate long SQL requirement.
- Do not re-enable built-in Skill desktop parameter preflight.
- Do not generate SQL locally or weaken SQL execution safety.

## Constraints

The executor remains responsible for SQL generation. The retry must preserve the selected source, verified fields, user filters and tool schema.

## Affected Areas

- `apps/desktop/src/main/assistantRuntime.ts`
- `apps/desktop/src/main/agentOrchestration/modelAdapters.ts`
- Focused prompt/runtime tests

## Invariants

- Truncated tool-call JSON is never executed.
- SQL is still generated by a model and executed only through the controlled tool path.
- Read-only, field-scope, approval and execution safety checks remain unchanged.
- SQL output token capacity remains sufficient for legitimate queries.

## Implementation Plan

1. Record log evidence and determine whether the token ceiling is legitimate.
2. Restore compact built-in Skill SQL contract injection.
3. Tighten initial and retry SQL parameter instructions.
4. Add a single truncation retry and focused tests.
5. Run targeted tests, typecheck, diff check and design review.

## Acceptance Criteria

- Built-in Skill SQL execution receives both the verified skeleton and its SQL parameter contract.
- The `sql` value is explicitly restricted to one SQL statement without explanation/schema/repetition.
- `PROVIDER_OUTPUT_TRUNCATED` on SQL triggers at most one compact retry.
- SQL `maxTokens` is not increased when the required query is short.

## Outcome

- Built-in system Skills now retain their stage-scoped SQL parameter contract even when the runtime has already produced a verified SQL skeleton.
- The generic SQL tool contract now explicitly rejects explanation, Schema copies, Markdown, JSON, comments, repeated clauses and repeated padding inside `sql`.
- A provider-truncated SQL tool call is discarded and retried once with the reasoning model using the verified skeleton and compact instructions.
- SQL output capacity remains 4,096 tokens because the failed task required a short query; increasing the ceiling would increase latency without addressing the observed generation failure.

## Follow-up

Monitor SQL parameter observations for repeat `PROVIDER_OUTPUT_TRUNCATED` events. Reconsider the ceiling only if a future trace proves a valid, non-repetitive SQL statement itself exceeds 4,096 completion tokens.
